## Core Domain Identity

This repository is the canonical development and distribution home for Jido-first Gralkor. The `JidoGralkor.*` layer owns Jido↔Gralkor wiring; the embedded `Gralkor.*` layer owns memory-domain behavior. Applications register Destinations as graph identities, then reference them from Lens ingestion and repository-YAML Reflection definitions whose writers select their extraction ontologies.

## World-to-Code Mapping

- **`JidoGralkor.Plugin`** — the Jido hook that watches `ai.react.query` / `ai.request.completed` / `ai.request.failed` signals and plants context / fires captures.
- **`JidoGralkor.Actions.MemorySearch` / `MemoryAdd` / `MemoryBuildIndices` / `MemoryBuildCommunities`** — the plugin's four ReAct tools; `MemorySearch` is the only recall path (no auto-recall in the plugin), and the two build actions are description-gated operator maintenance.
- **`JidoGralkor.ReAct.maybe_force_memory_search/2`** — folds `tool_choice` into the consumer's transformer overrides on iter-1, making recall agentic.
- **`JidoGralkor.Canonical.to_messages/3`** — normalises a Jido/ReAct turn into Gralkor's `[%Message{role, content}]` shape.
- **`JidoGralkor.Lifecycle`** — graceful-shutdown flush via the configured Gralkor client adapter's `flush/1`.
- **`JidoGralkor.ContextRotator`** — synchronous rotate-on-demand: flush, retain recent and in-flight entries, then install a fresh thread.
- **`Gralkor.Client` / `Gralkor.Ingest` / `Gralkor.Replace` / `Gralkor.Search`** — the callable memory boundary and request values. `Gralkor.IngestedRepresentation` records exactly `id`, `lens`, `content`, and `result`; producer-independent `Gralkor.Artefact` records exactly `id` and `payload`. `Gralkor.Destination` and its registry resolve graph names shared by Lenses and Reflection Destination outputs. `Gralkor.Lens`, `Gralkor.Lens.Replaceable`, and `Gralkor.Lens.Store` own ingestion behavior and Lens-specific graph replacement; the Reflection registry and runner load YAML processes, while the supervised scheduler and journal durably coordinate execution and each declared output per logical completion. The packaged operator Lens carries `Gralkor.DefaultOntology`; packaged ERL selects `Gralkor.Reflection.ERLOntology` on its Destination output.

## Ubiquitous Language

- *plugin* — `Jido.Plugin` mounted on a `use Jido` supervisor.
- *thread* — a Jido conversation segment; its `id` is the Gralkor `session_id`.
- *agent_name* — the assistant's display name; required at mount; renders all assistant turns in graphiti.
- *user_name* — the human's name per turn; stashed on `agent.state[:user_name]` by the consumer.
- *forced recall* — the iter-1 `tool_choice` override that pins `memory_search` on the first ReAct iteration.
- *operator* — the Jido `agent.id` (or the explicit `operator_id` supplied by a direct caller) whose `operator/<id>` graph is isolated; it does not determine global visibility.
- *Destination* — one registered graph name. `global` is the single shared graph, `operator` resolves to `operator/<operator id>`, and every application Destination resolves to its exact shared name. Lenses and Reflections reference Destinations by name; multiple may save to one.
- *Lens* — named ingestion or complete-graph replacement behavior referencing a Destination. The reserved `operator` Lens preserves implicit-default memory; a replaceable Lens changes only graph content marked as owned by that Lens.
- *Reflection* — an asynchronous synthesis process with its own name, programmatic or Lens-ingestion triggers, repository YAML Chain of Thought, exactly one Destination output, and at most one return-handler output. Its logical completion is `{operator_id, invocation_id, reflection_name}`; it runs ordered inference with trigger context, may call host tools as the current agent, and produces one deterministically identified, producer-independent artefact delivered to every declared output.
- *episode* — the unit written to graphiti with a declared source kind: `conversation` carries speaker-attributed text, `document` carries text, and `structured_record` carries JSON-encodable data. An episode search reads back the body that was written, while node and edge search return what the extractor derived from it.
- *fact* — the text of one edge an edge search returned together with its originating episode identifiers, source kinds, and source descriptions. Recall presents facts verbatim in search order with that attribution for the consuming agent to interpret.
- *node* — one entity graphiti extracted; node search returns entities directly, while edge search matches relationships by their endpoints.
- *entity description* — the sentence an ontology entity carries; graphiti's extractor reads it to decide when to mint that entity.
- *role* — one of the two inference slots, `llm` or `embedder`, each selecting its provider from its own model spec. The cross-encoder has no spec and follows the llm role; a credential is required only for a provider some role selects.

## Bounded Contexts

Two cooperating contexts live in this package: `Gralkor.*` owns the memory domain, while `JidoGralkor.*` adapts Jido signals, threads, actions, lifecycle, host tools, and tool context into that domain. Within Gralkor, Destinations name graphs, appending Lenses and Reflection Destination outputs own extraction, Lenses ingest without referring to one another, and Reflections run asynchronously from eligible Lens ingestion or programmatic invocations. Graphiti, Pythonx, and FalkorDB remain infrastructure inside the Gralkor context.

## Invariants

- Recall is LLM-driven via `MemorySearch`; the plugin never calls `Gralkor.Client.recall/4` directly.
- `session_id` is the Jido thread id from `agent.state[:__thread__].id` — never minted by the plugin.
- `agent_name` is required at mount; missing/blank raises `ArgumentError`.
- When a committed turn produces a non-empty capture, `user_name` is read from `agent.state[:user_name]`; missing/blank raises `ArgumentError`.
- First-turn-on-fresh-agent: no thread at query time → `MemorySearch` still searches for the current operator, and Lens mounts plant `agent_name` and the ingestion `lens` without a session id; capture is skipped only if no thread is committed when completion or failure is handled.
- A Destination name alone resolves placement: `operator` becomes `operator/<operator id>`; `global` and every application Destination remain their exact names for every operator. There is no scope or address syntax.
- Public search validates every Destination and Lens selector, result type, and positive result limit before any query begins. It defaults to episodes across every accessible registered Destination; optional Destination and Lens lists apply OR within each dimension and intersection across dimensions, with Lens filtering completed before each Destination's result limit. Results retain selected Destination order and identify their Destination plus originating Lens or declaring Reflection; Lens selectors require episodes, while explicit node and fact searches retain entity and edge type filters. Embedded episode writes are admitted one at a time through their shared local connection without admitting searches; remote writes remain concurrent except that deterministic UUID writes serialize through uniqueness-constrained, graph-clocked renewable claims whose generations atomically fence the episode, every derived entity and edge, and the completion marker across runtimes.
- Lens definitions are application-owned and selected by name. An appending Lens's callback controls zero, one, or many writes to its referenced Destination; a replaceable Lens validates one complete graph before replacing only content tagged with that Lens at the Destination, preserving other Lenses, Reflections, and unowned content. Public ingestion validates the declared source kind and its correlated content shape before invoking a Lens or Graphiti. Legacy `capture/5`, `memory_add/3`, `recall/4`, and the implicit `"operator"` Lens consistently use the packaged operator Destination and `Gralkor.DefaultOntology`; current capture and MemoryAdd writes carry trusted `operator` Lens provenance.
- Reflections are admitted only when their declared trigger is eligible and are isolated by `{operator_id, invocation_id, reflection_name}`. Lens-ingestion triggers wait for every intended Lens and receive completed representations containing exactly `id`, `lens`, `content`, and `result`; programmatic requests receive request content, host tools, and tool context under a caller-supplied replay-stable invocation ID. Direct ingestion validates its non-blank operator and replay-stable ingestion IDs before Lens storage; Lens-aware capture validates its non-blank operator before buffering, then mints one cryptographically collision-resistant ingestion ID per buffered ingestion and retains it across flush retries. Forwarded host tools receive the current `agent.id` as both `agent_id` and `operator_id`. Each Runner, Destination output, and return output phase has one active attempt; restart-safe phase data and retry deadlines survive scheduler or VM restart while runtime dependencies come from the replacement Scheduler; uncertain Destination writes are confirmed again before exhaustion; and completed phases do not rerun when a later output retries. Graceful shutdown awaits active capture flushes, closes Scheduler admission, and drains the Scheduler through a dedicated supervisor that remains responsive during root shutdown.
- Every valid Reflection has a unique name, exactly one registered Destination output with an extraction ontology, at most one return output whose handler implements the standard `return/3` callback, and a repository YAML CoT with ordered exact-output steps. Its stable artefact contains exactly `id` and `payload`, with the ID derived from its logical completion key; producer identity remains routing and episode provenance. Every output receives that exact artefact, Destination storage accepts an equal repeated ID and rejects conflicting immutable content, and return delivery is at-least-once. Before packaged generalisation inference, one default episode search covers every accessible registered Destination using every representation's content and returns related Lens-authored observations plus prior Reflection-authored generalisations. Each stored generalisation contains exactly `content`, evolution-depth `level`, and `evolves_from`; its historical snapshots contain only exact `content` and `level` from genuine influencing prior generalisations returned by that search and remain unchanged. The Runner rejects fabricated or altered snapshots, computes level `1` without predecessors or one greater than their maximum, and stores evolution results directly. Packaged ERL outputs to `operator` with `Gralkor.Reflection.ERLOntology`; packaged generalisation outputs to `global`. Destination artefact search returns relevant artefacts and may narrow to an exact `artefact_id`.
- Legacy recall presents every returned search fact verbatim and in order inside an untrusted memory block and makes no inference call of its own.

## Decision Rationale

- The iter-1 `tool_choice` forcing is a workaround: `Jido.AI.Reasoning.ReAct.Config` lacks a `:preamble_tool` knob, and `tool_choice` is applied uniformly across the ReAct loop today. The helper exists to pin it for one iteration without forking the strategy.
- Capture is not gated on calling a memory tool: completed turns with a committed thread are captured when their canonical trace is non-empty, while failed turns with a committed thread retain their terminal failure even when no prior event survived filtering. The selected Lens ingestion process decides downstream retention.
- Recalled graph content is memory context, not adjudicated truth. Source kind records deterministic origin rather than credibility or truth. Gralkor gives Graphiti's existing extraction call static guidance to preserve attribution and epistemic wording, then returns the search result's wording, order, and originating episode context without a separate presentation-classification inference; interpretation and truth-sensitive verification belong to the consuming agent, which can use its own model and conversation context.
- What graphiti derives from an episode is not knowable in advance: a statement naming one subject yields a node and no edge, and on another run may yield neither. Retrieval therefore matches the primitive to what was stored — episode search returns the body Gralkor wrote and must read back verbatim, node and edge search return what the extractor derived — and a custom entity type carries a description, because that is what the extractor reads to decide when to mint it.
- Consumer configuration is read from the `:jido_gralkor` app env and documented system environment variables. Registry-backed client operations resolve current settings per call; plugin mounts retain their resolved ingestion Lens, each MemorySearch invocation owns its selectors, and CaptureBuffer retains the Reflections loaded when it starts. Startup-owned configuration, including backend selection through `:falkordb` or `GRALKOR_DATA_DIR`, changes after an application restart.
- Ontology selection follows the memory writer: appending Lenses and Reflection Destination outputs default to open `DefaultOntology`, while packaged ERL selects `ERLOntology` so its artefacts can extract the library's `Learning` entity. Destinations remain schema-free graph identities.
- Generalisation and experiential learning are packaged Reflection declarations rather than Lens types: both operate over completed lensed information, while their YAML CoTs own synthesis behavior and their Destination outputs own extraction. Generalisation uses the default Search boundary once to revisit current and related observations with prior generalisations, then carry forward, combine, broaden, narrow, split, replace, or revise them as warranted; content-and-level snapshots preserve the chosen lineage as it existed at synthesis time. Artefacts remain producer-independent when several Reflections share a Destination.
- Reflection execution and host-tool effects are at-least-once because a crash can occur after an effect but before the scheduler observes the phase result. Canonical artefact persistence converges separately: stores create-or-confirm one deterministic ID and exact immutable artefact; Graphiti claims that ID in the graph across runtimes using graph-enforced UUID uniqueness and server-time leases, then publishes the episode, every extracted entity and edge, and its completion marker in one generation-fenced graph transaction. It resumes an equal deterministic unmarked episode without rerunning the Runner, converges matching historical duplicates before limiting search, and reports conflicting content explicitly. Unmarked pre-marker episodes stay hidden until verified migration or stable-ingestion replay establishes completion.
- The embedded Python dependency stack remains package-owned: `Gralkor.Python.init/1` supplies the packaged `priv/python/pyproject.toml` directly to `Pythonx.uv_init/1`, and `GraphitiPool` owns the shared local connection's write admission, socket timeout, and graphiti-core 0.29.3 empty-edge-candidate guard. Consumers may tune the embedded read timeout through `:embedded_falkordb_socket_timeout_ms` without restating Python dependencies or coordinating writes outside the package.
- Ontology-kwarg selection and inference-provider selection are made first in pure Elixir — `graphiti_boundary_spec/1` decides which `add_episode` kwargs an ontology populates, and `shared_client_spec/2` decides which provider builds each role's client and which OpenAI reasoning tier reaches Graphiti (`none` for GPT-5.5 and GPT-5.6, `auto` otherwise). Those decisions are pinned deterministically without Python, a real LLM, or credentials. Boundary data crosses as explicit arguments: the embedded interpreter shares the OS process but not Erlang's environment table, so `os:putenv` never reaches `os.environ` and `api_key!/1` hands each provider client its credential rather than letting Python read the variable.
- `Gralkor.Ontology` declares each relationship once (`from Source do verb Target end`) and derives graphiti's `edge_types` + `edge_type_map` automatically. Graphiti's split between those two dicts is the modelled-once-mentioned-twice trap the DSL exists to remove. `relationships: :scoped` does not forbid generic edges — graphiti always extracts edge candidates and only constrains *which named class* they conform to between declared `(src, dst)` pairs; closing the world on edges would require post-filtering not yet implemented.

## Temporal View

`ai.react.query` → plant `:session_id` when committed plus `:agent_name` and the selected ingestion `:lens`, retaining that Lens and host Reflection context on the request-correlated Jido thread entry → ReAct tools ingest through the configured or per-turn Lens while each MemorySearch independently searches default or selected Destination/Lens intersections, including before a thread exists → a completed request with a non-empty canonical trace, or a failed request with its terminal failure, is buffered when a committed thread exists → flush completes every Lens batch and collects each representation's `id`, `lens`, `content`, and `result` under one ingestion invocation ID → admit each eligible Reflection independently, with programmatic requests supplying their own invocation IDs → canonical Destination lookup → for packaged generalisation, search related episodes once across every accessible registered Destination → inspect observations and prior generalisations → evolve validated immutable `evolves_from` lineage and compute levels → produce one exact `id` / `payload` artefact → deliver it through the Destination output and optional standard return handler as independently journalled, at-least-once phases → remove durable work only after every output succeeds or reaches terminal exhaustion. With a committed thread, AgentServer termination starts a tracked fire-and-forget flush; application shutdown awaits every active or buffered flush, closes Scheduler admission, and drains Reflection work while the dedicated Reflection supervisor remains available for replacement. Manual rotation without a thread is a no-op; otherwise `JidoGralkor.ContextRotator.rotate_now/2` installs a fresh thread seeded with retained and in-flight entries only after a successful synchronous flush, and preserves the current thread when flushing fails.
